# 黑暗次元祭品：虚空馈赠

## 玩家操作

手持祭品对空气右键，或右键已经摆在地上的祭品，打开抽奖界面。对地面使用仍然放置摆件，对有效的未激活14格黑曜石门使用仍然优先启动原来的召唤仪式。

将物品放入中央单格，点击“献祭抽取”。每次消耗**该格整组物品 + 1000 点神秘之能**，奖励为一个物品。数量、耐久、附魔参与投入估价。能量不足、空格、无有效奖池均不扣费。创造玩家同样支付费用。

物品条滚动约5.5秒后停在金色指针处。奖品价值大于投入整组价值时播放升级和水晶的明亮音效；小于时播放低音与低沉音效；相等时播放短钟音。1000点神秘之能是固定费用，不折算为物品估值。音效以服务端估价比较为准，与物品稀有度颜色无关。

每位玩家都有独立投入格。关闭界面会退回尚未支付的物品；已经支付则立即发放先前选定的奖励。背包满时掉落在玩家身边并设置拾取归属。玩家数据保存投入与已确认奖励，登录和重生会恢复未结算物品。

## 自动奖池与概率

奖池来自服务端物品注册表，包含当前世界已启用的所有非空气物品类型，包括其他模组物品；没有按投入价格封锁高阶物品。奖品为该物品的默认实例、数量1，不枚举任意NBT、每一种附魔组合、创造标签页变体或容器内容。模组自定义的默认实例会保留其默认NBT。

初始估值来自品质、工具等级与耐久、护甲、防御韧性、食物营养及公共材料标签，原版常见矿物有稳定锚值。再对服务端配方图进行6轮有界估算，以最便宜配方成本修正结果，不能静态解析的动态配方保留物品属性估价。自定义物品无需编写专门的兼容分支。数据包重载后重建快照，不在每帧遍历注册表或配方。

投入总价值 `V` 的质量参数为 `q = ln(1+V)/(ln(1+V)+5)`；候选单位价值 `v` 的对数权重为 `(-1.4+3q)*ln(1+v/16)`。归一化前对每个候选保留正的权重下限，确保任意投入仍有机会抽到每一种候选。提高投入价值会把分布偏向更贵的物品，不能保证每次盈利。

默认对“奖品价值大于整组投入价值”的总概率作额外1.10倍调整，即相对提高10%，不是增加10个百分点。随后乘以玩家幸运系数：`max(0.1, min(100, 1 + 幸运属性 × 0.10))`。幸运属性包括原版幸运/霉运效果和其他模组装备提供的幸运。幸运I默认再提高10%，与基础提升相乘成为原始概率的1.21倍；霉运反向影响。调整保持各组内部相对权重，并保留其他物品的正概率。接近概率上限时进行保护，不能达到百分之百；若当前奖池没有价值高于投入的物品，幸运不会凭空生成更贵物品。界面左侧显示幸运影响，右侧显示基础好物加成。

配置 `goodRewardChanceMultiplier`（默认1.10）和 `luckBonusPerPoint`（默认0.10）可分别调整这两项规则。稀有度估价支持 Forge 扩展的枚举类型，不能再用仅覆盖原版四项的穷尽switch；异常物品属性/默认实例/配方钩子有保底估价，仍保留候选资格。

耐久损耗会降低投入价值；附魔按等级提供额外值。自定义名称、任意NBT字节数、容器所装内容不提供额外估值。估价是本系统的游戏规则，不等同于模组作者定义的交易价格或经济插件售价。

## 整合包覆盖估值

在世界的 `serverconfig/sourceofmystery-offering-server.toml` 中设置，例如：

```toml
valueOverrides = ["othermod:rare_crystal=2500", "minecraft:diamond=1024"]
```

覆盖值为单个物品的正整数（1至1,000,000,000）。未填写的物品自动估值；覆盖不会将任何物品移出奖池。修改后下一次计算使用新快照。若仅修改数据包配方，使用服务器的数据包重载流程。

## 服务端边界

客户端只发送原生菜单按钮点击，不能指定奖品、估价或随机种子。服务端检查菜单所有者、距离、方块是否存在、投入和能量；先选出结果，再在同一服务端线程提交支付和奖励。滚动期间投入格锁定，重复点击无效。客户端收到物品条仅负责表现，无法重抽。

实现位于 `com.sourceofmystery.offering`，界面为 `client.OfferingLotteryScreen`，结果协议为 `network.OfferingRollPacket`。新协议版本6，联机服务器和客户端需要安装相同版本。
